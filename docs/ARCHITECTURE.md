# ДомСигнал — архитектура

## Назначение и статус

Этот файл фиксирует только согласованные границы для параллельной разработки. Архитектурный walking skeleton будет реализован промптом №2 (`FND-01`); сейчас приложение и его инфраструктура отсутствуют.

## Границы

- Один репозиторий, один Python backend-пакет и один backend runtime image.
- `api` содержит HTTP API и MAX webhook; отдельный durable `worker` выполняет долгие задачи и доставку.
- Стартовая инфраструктура: PostgreSQL; без Redis, RabbitMQ, Kafka, pgvector, Kubernetes и отдельных HTTP-микросервисов.
- Направление зависимостей: `app/api`, `app/bot`, `app/worker` → `app/services` → `app/core`.
- `app/core` не зависит от FastAPI, MAX и SQLAlchemy; `app/services` координирует права, транзакции и доменные операции.
- `app/contracts` — общая граница DTO; UI не импортирует ORM и не дублирует бизнес-правила.
- `app/db` и `migrations` принадлежат DEV-A; опубликованные миграции не переписываются.
- `app/bot` и `miniapp` принадлежат DEV-B; bot вызывает services и не пишет в БД напрямую.
- `regions` содержит версионированные правила, контакты, календари и источники; непроверенные данные явно маркируются.
- `app/bootstrap.py`, общие контракты, CI и Compose — согласуемые узкие места с одним writer на изменение.

Фактическая структура, команды запуска и реализованные зависимости будут записаны здесь после выполнения и слияния промпта №2. Источник текущего направления — [implementation context](../IMPLEMENTATION_CONTEXT.md) и задача `FND-01` в [roadmap](../ROADMAP.md).

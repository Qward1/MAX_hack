# Сценарии ДомСигнала

Каждый сценарий — цепочка «кто → что прислал → что сделала система → какое
решение и кем принято → действие → результат». В скобках — тест-кейсы из
[`docs/qa/TEST_CASES.md`](qa/TEST_CASES.md) и автотесты, которые это проверяют.
Роли и входы — [`JURY_GUIDE.md`](../JURY_GUIDE.md), методы — [`API.md`](API.md).

Кто что решает — постоянное правило продукта: **ИИ** понимает текст, **правила**
находят опасность, **проверенный справочник** решает, кто отвечает, **оператор**
создаёт заявку из сигнала, **житель** подтверждает результат.

## 1. `/report` в домовом чате → заявка УК (основной путь)

| Шаг | Содержание |
|---|---|
| Actor | житель — участник подключённого домового чата MAX |
| Input | `/report во втором подъезде не работает лифт` |
| Processing | вебхук принимает событие (секрет, дедупликация по id события) → задача `inbound.report` в той же транзакции → воркер: маскирование, разбор (модель или правила), подъезд/этаж, категория «Лифт», опасность — правилами |
| Decision | справочник: лифт в доме — зона УК, которая управляет домом сейчас |
| Action | заявка `T-N` «Новая» в очереди УК; пост «Заявка T-N · Проблема с лифтом» с кнопками «Меня тоже касается» и «Открыть»; автору в личку — карточка |
| Result | оператор видит заявку в «Заявки» без перезагрузки; жители — в посте и на доске дома |

Альтернативы: автор не начинал диалог с ботом — ответ в группе с кнопкой «Начать»
(TC-059); сосед нажимает «Меня тоже касается» — присоединяется к той же заявке
(TC-058); маршрут внешний — карточка «куда обратиться» в личку (TC-060).
Проверки: TC-057, `tests/acceptance/test_jury_path.py`, живой MAX 19.09 и 24.09.

## 2. Работа по заявке и подтверждение жителем

| Шаг | Содержание |
|---|---|
| Actor | оператор УК, затем житель |
| Input | «Принять заявку» → «Начать работу» → «Сообщить о выполнении» (текст отчёта) |
| Processing | каждое действие — с `expected_version` и `Idempotency-Key`; переход проверяет `core/tickets.py`; событие пишется в неизменяемую историю |
| Decision | отчёт исполнителя **не закрывает** заявку: статус «Ждёт проверки жителями» |
| Action | пост в чате правится: «УК приняла в работу» → «В работе» → «Исполнитель сообщил о выполнении»; автору в личку «Проверьте, устранена ли проблема» с кнопками |
| Result | «Исправлено» → «Закрыта: жители подтвердили», проблема в «Решённые за 30 дней»; «Проблема осталась» → та же заявка `T-N` снова «В работе» |

Альтернативы: «Запросить уточнение» и «Ожидать другую службу» с возвратом
«Возобновить работу» (TC-041); отмена — только с причиной; две вкладки меняют
одну заявку — вторая получает 409 и обновлённую карточку (TC-043); двойной клик
и повтор запроса не создают второго действия (TC-096). Проверки: TC-035, TC-042,
`tests/integration/test_tickets.py` (32 теста).

## 3. Разговор соседей → сигнал → заявка

| Шаг | Содержание |
|---|---|
| Actor | несколько жителей в подключённом чате (чтение включено УК) |
| Input | «Лифт во втором подъезде опять не работает» / «Да, с утра стоит» / «Надо сообщить в УК» |
| Processing | реплики копятся в окно; после паузы (production — 30 секунд тишины, до 6 реплик) окно уходит в ИИ-пул: маскирование, роли реплик, подтип, подъезд; при отказе модели — правила |
| Decision | «проблема дома, сила — сильная»; повторы склеиваются в один сигнал; **заявку сам не создаёт** |
| Action | сигнал «3 реплики · 2 жителя · подъезд 2» с цитатами в «Сигналы» |
| Result | оператор: «Создать заявку» / «Присоединить к заявке» / «Внешний маршрут» / «Закрыть» с причиной |

Альтернативы: болтовня и объявления — сигнала нет; «починили» и «учебная тревога»
не создают проблему (TC-065). Проверки: TC-062, TC-063, `test_tc062…`.

## 4. Опасность

| Шаг | Содержание |
|---|---|
| Actor | житель в чате, в личке или в мини-приложении |
| Input | «В подъезде пахнет газом» |
| Processing | правила опасности **в транзакции приёма**, до модели и очереди |
| Decision | признак текущей опасности в этом доме; отрицание, прошлое время, «в доме напротив», учения — не опасность |
| Action | памятка в чат «При угрозе жизни и здоровью звоните 112» (не чаще раза в 30 минут на дом), оповещение оператора; в мини-приложении блок 112 первым, дубли не предлагаются |
| Result | от приёма до принятия памятки MAX — 0,67 с (живой MAX 24.09) |

Проверки: TC-039, TC-055, TC-064, TC-065.

## 5. Проблема не к УК

| Шаг | Содержание |
|---|---|
| Actor | житель |
| Input | «На улице у остановки не горят фонари» |
| Processing | подтип «уличное освещение», территория — улица; регион дома |
| Decision | справочник региона: не УК; официальный канал с источником и датой проверки (Казань — «Народный контроль», Москва — «Наш город») |
| Action | карточка «Проблема, вероятно, относится не к вашей УК», «Подготовить текст обращения», «Скопировать» |
| Result | «Я отправил(а) обращение» — отметка жителя, не регистрация во внешней системе; через 14 дней — «Пришёл ли ответ?» |

Альтернативы: «Всё равно сообщить в УК» (TC-040); ответственный не определён —
заявка «Нужно уточнение» без догадки (TC-037). Проверки: TC-036, TC-084–TC-087.

## 6. Дубль

Второй житель пишет о той же проблеме → «Похоже, об этом уже сообщали»: «Это та же
проблема» (присоединиться, число затронутых растёт) / «Нет, это другое» (новая
проблема). При опасности дубли не предлагаются. Проверки: TC-038, TC-053.

## 7. УК подключается сама

| Шаг | Содержание |
|---|---|
| Actor | представитель УК, затем администратор платформы |
| Input | заявка на `/company/apply`: название, ИНН, адреса домов |
| Processing | проверка формы, дубль ИНН, страница статуса по секретной ссылке |
| Decision | платформа одобряет с квотой чатов; адреса становятся заявками на дома; дом одобряется с регионом |
| Action | администратор УК создаёт свой вход (пароль + TOTP), приглашает сотрудников, подключает чат MAX по коду — бот проверяет свои права в чате |
| Result | свой кабинет, свои дома и чаты; другие УК ничего из этого не видят |

Проверки: TC-014–TC-024, TC-068–TC-070, `tests/acceptance/test_jury_path.py`
(15 шагов с эмулятором MAX, в том числе на чистом клоне).

## 8. Сообщество дома

Объявления и опросы УК и совета дома: черновик → «Предпросмотр получателей» →
отправка; пост в чате правится при изменениях; голос можно изменить до закрытия
опроса; итоги — только числами; отписка от рассылок уважается. Проверки:
TC-073–TC-080.

## Нестандартные ситуации

| Ситуация | Поведение | Где проверено |
|---|---|---|
| Пустое сообщение, одно слово | форма: «Опишите проблему хотя бы в нескольких словах — от 5 символов»; в чате — не проблема | TC-046; браузер 28.09 |
| Очень длинное сообщение | форма ограничивает 2 000 символов; сообщение чата — до 10 000, в буфер окна сохраняется усечённый текст, опасность правила ищут по всему тексту | TC-046; `services/passive_capture.py` |
| Бессмысленный текст | «Мы не уверены, что поняли всё правильно»; ответственный не выдумывается | браузер 28.09 (локальный стенд) |
| Несколько проблем в одном сообщении | ответ модели — список сигналов окна (схема `ai/resources/schemas/window_output.v1.json`), каждая проблема — свой сигнал | `tests/ai/`, оценка P6 (`evaluation/reports/2026-09-23-p6-evaluation.md`) |
| Нет адреса, подъезда | заявка на дом без подъезда; «Где: не определено» | TC-034 |
| Смена темы, болтовня | окно без проблемы — сигнала нет | TC-065, наборы `datasets/synthetic/` |
| Повтор обращения, дубль | «Похоже, об этом уже сообщали» | TC-038, TC-053 |
| Двойной клик, повторная отправка формы | один результат: `Idempotency-Key` + `expected_version` | TC-043, TC-096; прогон 28.09: повтор → тот же инцидент, другое тело → 409 |
| Повторный callback, повторная доставка события MAX | отбрасывается по id события (`inbox_receipts`) | `tests/integration/test_d1_personal_bot.py`, `test_chat_bindings.py`, `test_notifications.py` |
| «Проблема решена» в чате | не закрывает заявку — закрывает только подтверждение жителя в личке | TC-035 |
| «Проблема осталась», позднее возражение, несколько попыток | та же заявка в работу, номер не меняется, попытки в истории | TC-035, `test_tickets.py` tk06/tk07 |
| Вне компетенции УК | внешний маршрут (сценарий 5) | TC-036 |
| Модель недоступна, таймаут, неверный ответ, 429 | разбор правилами, предохранитель после 3 отказов, окно не теряется | TC-094; `evaluation/reports/2026-09-29-llm-probes.md` |
| Остановлен воркер | приём работает, задачи ждут и уходят после запуска | TC-092; прогон 28.09 |
| Перезапуск api / воркеров / базы / всего стека | готов за 0–4 с, данные на месте | TC-093; прогон 28.09 |
| Истёкшая сессия, повторный вход | 401 → экран входа, данные не теряются | TC-010 |
| Не та роль, чужой объект, неверный ID | 403 раздела / 404 объекта; «Раздел недоступен» или «Такой страницы нет» | TC-027, TC-044, `DATA-API.yaml` |
| Несуществующий адрес | API — 404 `problem+json`; кабинет — «Такой страницы нет» | `DATA-API.yaml` `unknown_route`; `f1.spec.ts` |
| Некорректный запрос | 422 `validation_error` с `field_errors` | `DATA-API.yaml` `max_login_validates_body` |

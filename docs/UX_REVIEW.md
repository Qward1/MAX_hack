Экран «до» у Ж3 и Ж1 на стенде раздут накопленными тестовыми проблемами
(у дома a1 их больше сотни); относительная разница показательна для экранов,
не зависящих от длины списка: проверка, проблема, карточка, черновик.

**Тест прищуривания** (первый экран, размытие 10 px, `test-results/ux/squint`):
на экране сигнала «после» различимы красный блок опасности, кнопка
«Позвонить 112» и синяя основная кнопка решения; «до» — одна синяя рамка без
действия в первом экране. На проблеме жителя «до» самым заметным был пустой
блок «Следующий шаг» с синей полосой, «после» — статус и строка «что дальше».
На проверке «до» первый экран занят доской (адрес, разделы, счётчик), сама
проверка начинается у нижнего края; «после» — заголовок шага и ответы с

## 5. Решения

| Что выбрано | Из чего | Критерий |
|---|---|---|
| Один `tokens.css` на все поверхности; кабинет — те же токены плотнее | отдельные палитры мини-приложения, кабинета и сайта (было) | одна система; контраст проверяется тестом |
| Компоненты проекта по метрикам MAX UI; MAX UI — провайдер темы и платформы | кнопки MAX UI с переопределением переменных | выключенное 2,4:1 и фиксированная высота у MAX UI; кабинет не грузит MAX UI; одна реализация |
| Первый дом + переключатель в шапке, адрес на шаге проверки | экран выбора при каждом входе; хранилище браузера (запрещено) | меньше шагов без риска молча отправить не в тот дом |
| Форма — отдельный экран, текст в памяти приложения | форма внутри доски (было) | ввод не теряется; «Назад» работает |
| Черновик открывается поверх своей карточки; результат формы заменяется | возврат к пустой форме | «Назад» ведёт к осмысленному экрану |
| «Назад» — по истории приложения; вход по ссылке — к родителю заменой записи | всегда «на доску» новой записью (было) | путь назад туда, откуда пришли, без тупика |
| Вкладки добавляют запись истории | вкладки без истории | привычное «назад» к предыдущему разделу |
| Подтверждение только у «Я отправил(а)» и отмены записи | подтверждать всё / ничего | необратимость |
| Знак статуса — в CSS `::before` с пустым альтернативным текстом | знак текстом в теге | тег читается одним словом, текст и цвет не единственный признак |
| Факты об официальном сервисе — раскрытием | всегда открыты (было) | основание, дата и «требует сверки» остаются открыты; действия — на первом-втором экране |
| Счётчики меню — `page.total` настоящих запросов, «тихие» к 401/403 | агрегат во frontend | не имитировать backend; сбой счётчика не выбивает сессию |
| Лендинг — только перевод на общие токены | переделка | порядок сокращения §11: лендинг первым |

## 6. Ограничения и риски

- Реальные клиенты MAX (iOS, Android, web) не проверялись: тема — по
  `prefers-color-scheme` (так же определяет MAX UI), `BackButton`, тактильный
  отклик и `enableClosingConfirmation` проверены только кодом и unit-тестами
  обёртки; в браузере без MAX они безопасно ничего не делают.
- Node.js 22.22 локально (в `package.json` — 24): проверки прошли на 22.
- Источники NN/g, GOV.UK и WCAG — по выжимке задания (на 26.09.2026);
  документация MAX Bridge открыта заново (методы HapticFeedback и closing
  confirmation сверены).
- Кабинет платформы, рассылки, уведомления, приём и обзор переведены на токены
  и тёмную тему, но их структура не перерабатывалась (P2/P3).
- Счётчики меню кабинета делают по запросу на дом (до 12 домов); при большем
  числе домов счётчик заявок не показывается — зависимость Z-3.

# ДомСигнал — контракты

## Назначение и статус

Здесь будет описана семантика общих DTO и публичных границ между backend, bot и mini app. Контракты будут реализованы промптом №2 (`FND-01`). Готовых endpoints, схем, миграций и generated types сейчас нет.

## Согласованные правила границы

- Источник схем после `FND-01`: Pydantic/FastAPI → OpenAPI → сгенерированные TypeScript types.
- Внешние MAX identifiers на JSON-границе передаются строками; время — timezone-aware UTC с пользовательским отображением по timezone региона.
- Bot/API нормализуют ввод, вызывают application service и получают DTO с разрешёнными действиями; ORM-объекты наружу не передаются.
- Групповой, личный и API-пути используют одну бизнес-логику.
- Публичный deep link не подтверждает членство или доступ к дому.
- Отметка пользователя о подаче не равна проверенной регистрации во внешней системе; источник номера и статуса хранится явно.
- Непроверенные нормативы и сроки имеют состояние `needs_verification`/`demo`; неизвестный срок не выдумывается.
- Контракт меняется совместимо либо единым согласованным набором producer + consumer + tests.

Первые фактические DTO, problem responses, OpenAPI и generated types должны появиться вместе с проверками в `FND-01`; до этого этот документ не является обещанием доступного API.

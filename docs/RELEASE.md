# Выпуск и витрина

Онлайн-сдача — **30.09.2026 12:00 МСК**; проверка жюри — до 14.10; финал — 29.10,
Казань. Production собирается из ветки `main`; версия сдачи — коммит под тегом
`online-submission-final`.

## Как выпускается версия

1. Проверки на коммите выпуска: `uv run python scripts/check.py --scope all`
   (вместе с интеграцией на PostgreSQL), `npm --prefix=miniapp run test:browser`,
   приёмка `uv run python scripts/acceptance_run.py --target local` — наборы и
   запуск описаны в [`TESTING.md`](TESTING.md).
2. Выкладка на сервер — [`deploy/README.md`](../deploy/README.md), раздел
   «Safe redeploy»: копия базы до выкладки, образ прежней версии под тегом для
   отката, `BUILD_COMMIT`, пересборка, затем `/ready`, `/version` и вебхук без
   секрета → 401.
3. Проверка выпуска — `scripts/release_check.py` (ниже), все строки OK.

**После 30.09 12:00 код не меняется** (условие задания). Допустимы только
действия с данными через штатные инструменты (восстановление витрины ниже) и
эксплуатация сервера — [`OPERATIONS.md`](OPERATIONS.md).

## Как проверить версию

```bash
git rev-parse online-submission-final^{commit}
curl https://domsignal.176-108-244-168.sslip.io/version
uv run python scripts/release_check.py --fetch
```

`/version` production возвращает коммит под тегом `online-submission-final`; боту
в MAX можно отправить `/version`. Тег аннотированный: `git rev-parse
online-submission-final` без `^{commit}` вернёт объект тега, а не коммит.
Короткий вид коммита — первые 7 символов.

`release_check.py` проверяет: рабочее дерево чистое; `HEAD` = `origin/main`;
`/version` production = `HEAD` (или после него в `main` пришли только документы —
`docs/`, `*.md`, `evaluation/reports/`: код образа тот же); `/ready`; вебхук без
секрета → 401; OpenAPI из кода = `docs/openapi.json`; gitleaks по коммитам с
прошлого выпуска. Последняя строка — репозиторий, коммит и дата выпуска; если
после выкладки пришли только документы, это коммит из `/version`, а не `HEAD`.

## Витрина жюри

Витрина — демо-УК «Пилотная, 7», её дом «Казань, ул. Пилотная, 7», демо-чат и
проверочные аккаунты жюри; все они — тестовые данные. Проверочные аккаунты не
могут её сломать: разрушающие действия над витриной получают 403
`showcase_protected`. Обычные сотрудники и администраторы платформы таких
ограничений не имеют.

Самопроверка — раз в сутки задание `showcase` в `.github/workflows/uptime.yml`
(при нарушении открывает issue в репозитории); вручную:

```bash
SHOWCASE_CHECK_TOKEN=… python scripts/showcase_check.py
```

Каждый инвариант `showcase_check.py` восстанавливается штатно, без правки базы
руками. Команды `python -m domsignal.tools.*` — на сервере:
`sudo -n docker compose -p domsignal-prod exec api python -m …`; каждая
пишет квитанцию с оператором и причиной.

| Инвариант (`showcase_check.py`) | Как восстановить |
|---|---|
| витрина отмечена | `python -m domsignal.tools.showcase mark-company --company-id <id УК> --operator <кто> --reason <почему>` |
| УК витрины активна | кабинет платформы (суперадмин) → «Организации» → УК «Пилотная, 7» → «Возобновить организацию» с основанием |
| квота не меньше подключённых чатов | там же → «Квота чатов» → «Изменить квоту» (не меньше числа подключённых) |
| управление демо-домом действует | кабинет УК → «Дома» → «Запросить управление домом» на тот же адрес → кабинет платформы → «Заявки на дома» → «Одобрить управление», регион RU-TA / Казань |
| открытый доступ к демо-дому включён | кабинет УК (администратор УК витрины, не проверочный аккаунт) → «Дома» → «Включить открытый доступ» → «Подтвердить: включить» |
| демо-чат подключён | владелец демо-чата в MAX: бот — администратор группы с правом читать все сообщения; кабинет УК → «MAX-чаты» → «Подключить чат» → команда боту в личку → «Подтвердить подключение» |
| чтение демо-чата включено | кабинет УК → «MAX-чаты» → «Включить чтение чата» → «Подтвердить: включить» |
| бот в демо-чате | владелец демо-чата снова добавляет бота администратором; затем строка «демо-чат подключён» |
| проверочные аккаунты есть / в штате УК витрины | `python -m domsignal.tools.showcase create-reviewer-staff --company-id <id> --role company_admin\|operator --login-name <логин> --display-name "Проверяющий (УК)" --operator <кто> --reason <почему>`; первый вход — `scripts/jury_setup.py`, данные — в закрытую передачу |
| вход проверочных аккаунтов не отозван | заблокирован после неудачных попыток — подождать 5 минут или выдать резервный комплект; отозван — `python -m domsignal.tools.employee_auth reset-password` / `reset-mfa` для этого пользователя и снова `scripts/jury_setup.py` |

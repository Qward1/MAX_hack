# Как запустить и проверить модуль

Этот модуль читает сообщения из консоли или файла и возвращает предварительные сведения о проблеме дома. Он **не отправляет сообщения в приложение**, не создаёт настоящие заявки и не обращается к языковой модели через интернет. Ключи API ему не нужны.

## Что понадобится

- Python 3.10 или новее. Команды ниже написаны для PowerShell в Windows.
- Папка `ml/` из ветки `ml/standalone`. Команды выполняются **из корня этой рабочей копии**, где видна папка `ml/`.
- Для проверки качества и для обучения — отдельная папка с **реальным размеченным набором v3.0**. На машине автора он лежит в `C:\Users\Dimentiy\repoVScode\MAX_hack\datasets`. Именно этот набор домовых чатов **не входит в Git**; в клоне есть другие служебные и искусственные файлы под именем `datasets/`, но они не заменяют v3.0. В другом месте передайте свой путь через `--data-root "C:\путь\к\datasets"`. Реальный набор предназначен только для участников проекта; не добавляйте его в открытый репозиторий. Для обработки одного сообщения или примера чата данные не нужны, если веса уже подготовлены.
- Для лёгкого варианта — файл `ml/artifacts/light.joblib`. Для усиленного — дополнительно файлы весов и локальный кэш E5. Веса намеренно не хранятся в Git: это большие файлы, полученные при обучении. В рабочей копии автора они уже есть; в чистом клоне их потребуется создать.

Проверить установленный Python и перейти в рабочую копию (если она лежит в другом месте, замените путь в команде `cd`):

```powershell
python --version
cd C:\Users\Dimentiy\repoVScode\MAX_hack_ml_standalone
```

## Быстрый запуск в подготовленной рабочей копии

Установить зависимости усиленного варианта и проверить наличие всех файлов:

```powershell
python -m pip install -r ml/requirements-embeddings.txt
python ml/check.py --engine heavy --data-root ..\MAX_hack\datasets
```

Если проверка напечатала `"ready": true`, можно пользоваться усиленным вариантом. Если `ready` равно `false`, поля `missing_packages`, `missing_files`, `e5_cached` и `data_ready` показывают, чего не хватает. Отсутствие `datasets` мешает только обучению и оценке качества, но проверка с указанным `--data-root` тоже пометит это как ошибку. Для обработки готовой моделью запустите `python ml/check.py --engine heavy` без пути к данным.

**Одно сообщение:**

```powershell
python ml/cli.py single --engine heavy --text "В подъезде нет горячей воды"
python ml/cli.py single --engine heavy --text "Соседи, во сколько сегодня собрание?"
python ml/cli.py single --engine heavy --text "Люди застряли в лифте, вызовите помощь"
```

На весах этой рабочей копии первый пример получил `is_problem: true`, `fine_class: no_hot_water`; второй — `is_problem: false`; третий — `fine_class: elevator_trapped`, `emergency: true`. Это вымышленные тексты для проверки, а не доказательство качества на новых домах. Числовые оценки могут измениться после переобучения.

Сокращённый ответ на первое сообщение (настоящая команда выводит и другие поля):

```json
{"is_problem":true,"fine_class":"no_hot_water","product_category_suggestion":"water","recipient_hint":"uk_or_resource_supplier","emergency":false}
```

**Несколько сообщений об одной проблеме:**

```powershell
python ml/cli.py chat --engine heavy --merge-policy service_context_6h --file ml/examples/demo_chat.jsonl
```

Файл примера содержит три вымышленных сообщения: сначала жалоба на горячую воду во втором подъезде, через пять минут подтверждение той же проблемы, затем сообщение «воду дали». В результате первая строка имеет действие `created_preliminary` и заявку `case-1`, вторая — `attached` к `case-1`, третья — `resolution_pending_human`. Заявка после третьей строки **остаётся открытой**: сообщение жителя само по себе не подтверждает устранение. Поле `open_cases` показывает текущие открытые заявки. Вся история хранится только в памяти этого запуска.

Для второго сообщения существенная часть ответа выглядит так: `"event":{"action":"attached","case_id":"case-1"}`. Это означает, что новая заявка не создана, а сообщение добавлено к существующей.

Для своего файла используйте одну запись JSON на строку. Пример двух строк:

```jsonl
{"id":"a1","house_id":"house-1","ts":"2026-09-28T10:00:00+03:00","text":"В третьем подъезде не работает лифт"}
{"id":"a2","house_id":"house-1","ts":"2026-09-28T10:04:00+03:00","reply_to":"a1","text":"Подтверждаю, лифт в третьем подъезде стоит"}
```

Сохраните их в файл, например `ml/artifacts/my_chat.jsonl`, и передайте его через `--file`. Поле `text` обязательно; `id`, время `ts`, идентификатор дома `house_id` и ссылка на сообщение `reply_to` помогают правильно объединять обращения. `house_id` должен быть одинаковым для одного дома. Время лучше записывать с часовым поясом. Необезличенные переписки не добавляйте в Git. Режим `replay` принимает тот же формат и нужен для повторного прогона сохранённой ленты.

**Проверить качество на размеченном наборе v3.0:**

```powershell
python ml/cli.py eval --engine heavy --split test --data-root ..\MAX_hack\datasets --output ml/artifacts/my_eval.json
```

В консоль выводятся общие показатели отдельно для WhatsApp и Telegram; полный отчёт сохраняется в указанный файл. Исходные тексты не выводятся. Используйте `--split val` для настроечной части и `--split test` для проверочной. Не подбирайте настройки по результатам `test`: иначе проверка качества перестанет быть независимой. Эти показатели сравниваются с разметкой моделью, а не с подтверждёнными людьми метками.

В кратком ответе `gate_ap` оценивает обнаружение проблемы, `gate_precision` и `gate_recall` означают точность и полноту первого этапа, `class_macro_f1` — среднюю F1 определения вида **при уже известном наличии проблемы**, а `end_to_end_macro_f1` — среднюю F1 **всей системы** на всех сообщениях. Для общей оценки используйте именно последний показатель. В полном файле он находится в разделе `end_to_end_classes_all_messages` каждого чата; там же есть результаты по отдельным видам проблем и диапазоны неопределённости.

## Если усиленные веса отсутствуют

Лёгкий вариант требует меньше памяти и работает на обычном процессоре:

```powershell
python -m pip install -r ml/requirements.txt
python ml/check.py --engine light
```

Если отсутствует `ml/artifacts/light.joblib`, но доступен набор v3.0, обучите его локально. Отчёт обучения и веса сохранятся в игнорируемой Git папке `ml/artifacts/`:

```powershell
python ml/cli.py train --variant best --data-root ..\MAX_hack\datasets --artifact ml/artifacts/light.joblib --output ml/artifacts/train_report.json
python ml/check.py --engine light
python ml/cli.py single --engine light --text "В подъезде нет горячей воды"
python ml/cli.py chat --engine light --merge-policy service_context_6h --file ml/examples/demo_chat.jsonl
```

Для подготовки усиленных весов с нуля нужны открытые веса E5 и ruBERT, набор v3.0 и обучение по разделу «Воспроизведение усиленного варианта» в [главном описании](../README.md#воспроизведение-усиленного-варианта). **Пользование уже подготовленными весами не скачивает модель из интернета**; первоначальная загрузка открытых весов для обучения требует подключения, но не ключа платного API. Без данных и без весов чистый клон не сможет классифицировать сообщения.

## Как читать результат

Программа печатает JSON: названия полей оставлены на английском для будущего подключения к приложению.

| Поле | Значение |
|---|---|
| `is_problem` | Считает ли модель сообщение сообщением о проблеме дома. |
| `fine_class` | Подробный класс из набора данных; например, `no_hot_water` — нет горячей воды. При `is_problem: false` значение пустое. |
| `product_category_suggestion`, `product_subtype_suggestion` | Предварительные категория и подтип для приложения. |
| `recipient_hint` | Подсказка о типе адресата, **не подтверждённая организация**. |
| `utterance` | Жалоба, вопрос о состоянии, сообщение об устранении и т. п. |
| `emergency`, `urgent_human_review` | Оценка экстренности и отдельный признак для срочного просмотра. Экстренная модель пропускает часть случаев; эти поля не заменяют процедуру реагирования. |
| `confidence` | Числа, которыми модель обосновывает решение. Оценка класса ещё не откалибрована и не равна вероятности без ошибки. |
| `slots` | Упомянутые в тексте подъезд и этаж. |
| `requires_human_confirmation` | Информационная пометка. Консоль работает без оператора и не ждёт подтверждения. |
| `event.action`, `event.case_id` | Только в `chat`/`replay`: что произошло с предварительной заявкой и её номер в текущем запуске. |

Команда `python ml/cli.py --help` показывает режимы; `python ml/cli.py single --help` показывает параметры конкретного режима. Дальнейшее устройство и ограничения описаны в [главном описании](../README.md).

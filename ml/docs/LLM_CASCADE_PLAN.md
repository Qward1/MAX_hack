# Выборочное обращение к языковой модели (исследование)

**Итоговый `ml/cli.py` полностью локален: языковую модель не вызывает, ключ не читает и для запуска ключа не требует.** Всё ниже относится к отдельному небольшому исследованию с внешними провайдерами языковых моделей или к гипотезе будущей интеграции. Исследование выполнено 27.09.2026: 114 ограниченных вызовов на 9,14 ₽ суммарно. Основания включать языковую модель в модуль оно не дало. Технический протокол — [RESEARCH_ROUND3.md](RESEARCH_ROUND3.md#ограниченное-исследование-с-внешними-моделями).

## Для чего вызывать языковую модель

1. Локальные модели первого этапа и класса обрабатывают все сообщения и остаются основным путём. Порог первого этапа и отрыв двух лучших классов позволяют заранее выбрать трудные 5–10% сообщений.
2. В чате первыми кандидатами становятся короткие сообщения рядом с открытой заявкой, которые первый этап отклонил, а также ответы `reply_to` и конфликт класса с открытой заявкой. Модель получает только это сообщение и 1–3 безопасно обезличенных фрагмента уже открытых заявок. Задача — решить `problem / no_problem / unclear`, предложить класс из локального короткого списка и `same_case / new_case / unclear` для конкретной открытой заявки. Ответ не создаёт и не закрывает заявку автоматически.
3. В нынешнем автономном CLI языковая модель не вызывается, а предварительные класс и связь выдаются сразу. Если впоследствии появится оператор, он сможет проверить `unclear` и спорные случаи. Без такой проверки ответы модели не следует использовать как истину для дообучения.

## Выбор модели и стоимость

Кандидаты исследования — GigaChat 2, Qwen 3.6 35B, DeepSeek V3.2 и gpt-oss-120b, каждый через маршрут конкретного провайдера с хранением данных в РФ; автоматический выбор маршрута запрещался, резервный маршрут отключался. Цены российских маршрутов заметно выше цены по умолчанию в карточке модели, поэтому их нужно повторно считывать перед каждым экспериментом. Исследовательский бюджет — максимум 10 ₽ суммарно и 100 запросов на модель. Из-за токенов рассуждения проверялись лимиты 300, 800 и 1 600 выходных токенов. Фактические токены, рубли и задержка учитываются по ответу API. Любой запрос без подтверждённого российского маршрута запрещён.

## Протокол оценки

- До вызова зафиксировать выбранные окна и разметку, не используя ответы модели. Независимая метрика требует отдельной проверки человеком.
- Отправлять только минимальный контекст после строгой проверки персональных сведений. Исходные тексты набора обезличены не полностью; при сомнении окно пропускать. Исходные или отправленные тексты, ответы модели и API-ключ не выводить в консоль и не сохранять в Git.
- Сравнить на **одних и тех же** окнах: без модели и с каждым кандидатом. Считать точность решения о проблеме, класса, парной связи и итоговый F1 связей, число ручных проверок, долю сообщений, ушедших в API, p50/p95 задержки и цену. Ошибки модели не считаются эталоном.
- Принять выборочное обращение лишь при измеренном выигрыше на независимой человеческой разметке с сохраняющейся точностью связей; иначе оставлять модель подсказкой оператору.

## Ключ без передачи в чат

Ключ для исследования хранился в локальном файле в `ml/artifacts/`; `ml/.gitignore` исключает все файлы `artifacts/*`. Этот файл читает только исследовательский скрипт при явном `--live`. Финальный CLI ключ не читает, файл не поставляется с репозиторием и не нужен пользователю. При возможной будущей интеграции секрет должен храниться на сервере вне Git и клиентской машины.

Исследовательский скрипт в `experiments/06_llm_cascade/` по умолчанию делает только `dry-run` на вымышленных окнах из `examples/`. Его необязательные зависимости находятся в `ml/requirements-llm-pilot.txt`. Реальный запуск требует явный `--live` и заранее размеченный, проверенный на личные сведения JSONL. Скрипт повторно проверяет российский флаг провайдера и актуальную цену, закрепляет провайдера без резервного маршрута, прекращает запросы при верхней границе 10 ₽ или 100 запросов **за один запуск** и пишет только решения и числа токенов. Промпты и ответы не сохраняются. Это экспериментальный инструмент, не вызов модели из основного `single/chat/eval`.

## Решение после исследования

Выборки исследования были малы, а независимого эталона нет, поэтому ни одна модель не выбрана ни для автоматической склейки, ни для включения в модуль. Для следующей **экспериментальной** очереди сложных классов по цене за исправленную локальную ошибку рациональнее Qwen; gpt-oss-120b реже ошибался в формате ответа.

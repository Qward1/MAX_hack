# Выборочный LLM-каскад через Polza.ai

Статус на 27.09.2026: пользователь разрешил ограниченный платный эксперимент и поместил ключ в игнорируемый Git локальный файл. Выполнено 114 ограниченных вызовов на 9,1394 ₽; доказанной прибавки на независимом реальном потоке пока нет. Результаты и ограничения — [RESEARCH_ROUND3.md](RESEARCH_ROUND3.md). **Итоговый `ml/cli.py` полностью локален: LLM не вызывает, ключ не читает и для запуска ключа не требует.** Всё ниже относится к отдельному исследовательскому пилоту или гипотезе будущей интеграции.

## Для чего вызывать LLM

1. Локальные gate и классификатор обрабатывают все сообщения. Они остаются основным путём. Порог gate и отрыв двух классов позволяют заранее выбрать трудные 5–10% сообщений.
2. В чате первыми кандидатами становятся короткие сообщения рядом с открытой заявкой, которые gate отклонил, а также ответы `reply_to` и конфликт класса с открытой заявкой. LLM получает только это сообщение и 1–3 безопасно обезличенных фрагмента уже открытых заявок. Задача — решить `problem / no_problem / unclear`, предложить класс из локального короткого списка и `same_case / new_case / unclear` для конкретной открытой заявки. Ответ не создаёт и не закрывает заявку автоматически.
3. В нынешнем автономном CLI LLM не вызывается, а предварительные класс и связь выдаются сразу. Если впоследствии появится оператор, он сможет проверить `unclear` и спорные случаи; текущий этап не зависит от этой проверки. Без неё API-ответы не следует использовать как истину для дообучения.

## Выбор российской модели и стоимость

Каталог Polza `GET /api/v1/models?type=chat&include_providers=true` проверен 27.09.2026. Модель должна иметь **конкретного** провайдера со `stores_data_in_russia=true`; сам фильтр модели недостаточен, потому что автоматический маршрут часто дешевле и зарубежный. Источники: https://polza.ai/docs/gaidy/models , https://polza.ai/docs/gaidy/provider-selection , https://polza.ai/security .

| Кандидат и закреплённый провайдер | Вход/выход, ₽ за 1 млн токенов | Оценка 800 входных + 100 выходных | Роль в пилоте |
|---|---:|---:|---|
| `sber/gigachat-2`, `sber-gigachat` | 91 / 91 | 0,082 ₽ | Дешёвая базовая LLM |
| `qwen/qwen3.6-35b-a3b`, `yandex` | 280 / 70 | 0,231 ₽ | Лучшее соотношение цены и найденных ошибок в маленьком пилоте, но часть ответов требует большего лимита |
| `deepseek/deepseek-v3.2`, `yandex` | 700 / 1120 | 0,672 ₽ | Один дорогой невалидный технический ответ; пока не выбран |
| `openai/gpt-oss-120b`, `yandex` | 420 / 420 | 0,378 ₽ | Чуть выше наблюдаемое качество, заметно дороже Qwen; тоже только кандидат |

Цены с российского маршрута заметно выше цены по умолчанию в карточке модели. Их нужно повторно считывать перед каждым экспериментом. Провайдер закрепляется через `provider.only` и `allow_fallbacks: false`. Исследовательский бюджет — максимум 10 ₽ суммарно, максимум 100 окон на модель; текущая сумма 9,1394 ₽. Из-за токенов рассуждения проверялись лимиты 300, 800 и 1 600 выходных токенов. Фактические токены, рубли и задержка учитываются по ответу API. Любой запрос без подтверждённого российского провайдера запрещён.

## Протокол оценки

- До вызова зафиксировать выбранные окна и разметку, не используя ответы LLM. Старые `val` и ручная разметка ассистента дают исследовательскую оценку; независимая метрика требует отдельной проверки человеком.
- Отправлять только минимальный контекст после строгой проверки персональных сведений. Исходные тексты в `datasets/` обезличены не полностью; при сомнении окно пропускать. Исходные или отправленные тексты, ответы модели и API-ключ не выводить в консоль и не сохранять в Git.
- Сравнить на **одних и тех же** окнах: без LLM, GigaChat2, Qwen35b и gpt-oss-120b. Считать точность решения о проблеме, класса, парной связи и итоговый pair F1, число ручных проверок, долю сообщений с API, p50/p95 задержки и цену. Малый технический пилот пока не даёт итоговый pair F1; ошибки LLM не считаются эталоном.
- Принять каскад лишь при измеренном выигрыше на независимой человеческой разметке с сохраняющейся точностью связей; иначе оставлять LLM подсказкой оператору.

## Ключ без передачи в чат

Для прошлого эксперимента владелец поместил ключ в `ml/artifacts/polza_key.txt` этой рабочей копии. `ml/.gitignore` исключает все файлы `artifacts/*`; только экспериментальный скрипт при явном `--live` читает этот файл. Финальный CLI ключ не читает, файл не поставляется с репозиторием и не нужен пользователю. Скрипт пилота не выводит ключ, однако любой запущенный с доступом к файлу процесс технически может его прочитать; поэтому при возможной будущей интеграции секрет должен храниться на сервере вне Git и клиентской машины.

Скрипт `experiments/06_llm_cascade/polza_pilot.py` по умолчанию делает только `dry-run` на вымышленных окнах из `examples/polza_pilot_synthetic.jsonl`. Его необязательные зависимости находятся в `ml/requirements-llm-pilot.txt`. Реальный запуск требует явный `--live` и заранее размеченный, проверенный на личные сведения JSONL. Он повторно проверяет российский флаг провайдера и актуальную цену, закрепляет `provider.only` с `allow_fallbacks=false`, прекращает запросы при верхней границе 10 ₽ или 100 запросов **за один запуск** и пишет только решения и числа токенов. Суммарный бюджет нескольких запусков отслеживался отдельно; сейчас он исчерпан почти полностью. Промпты и ответы не сохраняются. Это экспериментальный инструмент, не вызов LLM из основного `single/chat/eval`.

## Решение после пилота

На 24 безопасных переформулировках локальная модель дала 10/16 правильных классов, Qwen 12/16, gpt-oss-120b 13/16; для связи Qwen 4/8, gpt-oss-120b 5/8. На десяти заранее выбранных трудных синтетических сообщениях локальная модель дала 2/10, Qwen 4/10 за 0,7902 ₽, gpt-oss-120b 5/10 за 1,4860 ₽. Эти числа слишком малы, а независимого эталона нет. Qwen рациональнее для следующей **экспериментальной** очереди сложных классов по цене за исправленную локальную ошибку; gpt-oss-120b имеет небольшое наблюдаемое преимущество качества и меньше ошибок формата. Для автоматической склейки ни одну модель не выбирать: на текущих данных её надёжность не подтверждена.

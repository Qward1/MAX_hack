# План ограниченного LLM-эксперимента — ещё не запускался

Статус на 27.09.2026: платные запросы **не выполнялись**. Перед ними нужно явное разрешение владельца данных на API-расход и передачу фрагментов переписки внешнему провайдеру. Ключ должен быть в локальной переменной окружения, не в файле репозитория и не в сообщении чата.

## Гипотеза

Текущий усиленный ML-вариант пропускает 39 из 99 сообщений с инцидентом на двух размеченных днях. Особенно трудны короткие продолжения разговора без явного класса. LLM получает только текущее сообщение, 3–5 предшествующих сообщений этого дома, список открытых предварительных заявок с краткими классами и возвращает структурированный ответ: `is_problem`, `class`, `link_to_existing_case` либо `new_case`, `resolution_candidate`, `needs_human_review`. Это проверяет способность LLM разрешать контекст и связь, а не заменяет локальный классификатор на каждом сообщении.

## Дизайн проверки

1. До API-вызова выбрать максимум 100 неоднозначных окон из новых дней по **локальным** признакам: слабая уверенность gate, конфликт класса, короткая реплика рядом с открытой заявкой. Сначала разметить их вручную ассистентом, не показывая ему предсказания LLM. Сохранить только индексы и хеши; исходные тексты и идентификаторы в журнал не писать.
2. Проверить и усилить обезличивание перед отправкой: исходные данные названы обезличенными, но это не гарантирует отсутствия имён, телефонов и адресов в поле текста. Для каждой отправки оставить только минимальный контекст, заменить обнаруженные персональные сведения маркерами. Если безопасная подготовка невозможна, окно пропустить.
3. Одни и те же окна запустить через `gpt-5-mini` и `gpt-5.4-mini` с фиксированным JSON Schema и одинаковой инструкцией, без поиска и дополнительных инструментов. Сравнить с локальным heavy + `service_context_6h` и с заранее зафиксированной разметкой ассистента. Такой результат будет исследовательским; для независимой оценки выбранные окна затем должен проверить человек. Само решение LLM не считать эталоном.
4. Считать качество связи (pair precision/recall/F1), долю пропущенных проблем, ложных заявок, ошибки адресата, количество ручных проверок, задержку p50/p95 и фактические входные/выходные токены. Показывать прирост вместе с дополнительной ценой, а не только лучшую F1.
5. Ограничить вызовы: до 100 окон на каждую модель, не более 2 000 входных и 300 выходных токенов на запрос; остановка при совокупном API-расходе **$3**. Это верхняя техническая граница, а не обещание фактической суммы. Если бюджет или приватность требуют меньшего лимита, сократить выборку до запуска.

На 27.09.2026 официальная цена `gpt-5-mini` — $0.25 за 1 млн входных и $2 за 1 млн выходных текстовых токенов; `gpt-5.4-mini` — $0.75 и $4.50. При максимуме 100×(2 000 входных + 300 выходных) для каждой модели расчётная цена текста составляет около **$0.40** до возможных дополнительных расходов и изменения тарифа; лимит $3 оставляет запас на служебные токены и повторы. Источники: https://developers.openai.com/api/docs/models/gpt-5-mini и https://developers.openai.com/api/docs/models/gpt-5.4-mini . Обе модели поддерживают структурированный вывод по JSON Schema: https://developers.openai.com/api/docs/guides/structured-outputs .

Порог успеха для дальнейшей разработки: рост F1 связей на проверенной человеком выборке без снижения precision ниже 0.90, при ограничении ручной нагрузки и полной стоимости. До человеческой проверки этот критерий не считается выполненным. Если критерий не выполнен, оставить LLM только как необязательную подсказку оператору.

# Раунд 2: исследование и гипотезы (26.09.2026)

Этот план зафиксирован **до** новых экспериментов. Никакие тексты не уходят во внешние API; скачивание открытых весов возможно, платные вызовы требуют отдельного согласования. `test` используется после выбора на `val`.

Итоги проверки приведены в конце файла. Исходные гипотезы выше сохранены без ретроспективного редактирования.

## Диагноз первого раунда

- Основная цифра класса должна учитывать **всю** цепочку `gate → fine class` на всех сообщениях. Изолированная голова на заведомых проблемах даёт WA/TG test 0,771/0,674 macro-F1, но полная цепочка только 0,619/0,513. Гейт теряет четверть проблем, и их класс автоматически превращается в `not_a_problem`.
- Датасет имеет 33 проблемных класса с длинным хвостом. Некоторые встречаются в реальном train 1–10 раз. Синтетика помогает классу, но стиль синтетики отличим. Опубликованная базовая линия на всех метках уже 0,640/0,494 macro-F1. Прогресс нужно мерить против неё на **той же постановке**, а не по условной голове.
- Замороженные эмбеддинги E5 без адаптации к этой задаче проиграли символьному TF-IDF на `val`; это не является проверкой дообученного BERT. Обучение только линейной головы не меняет представление коротких бытовых реплик.
- Для склейки нет человеческих меток инцидентов. `pairs/dev_pairs.jsonl` — эвристические пары, частично определённые классом и временем. Метрики на них могут служить отладкой, а не оценкой качества заявок.

## Обоснование подходов

- **Плоская 34-классовая модель** может убрать накопление ошибок двух этапов. Иерархическую модель оставляем как сравнительный вариант, поскольку она позволяет отдельно задать рабочую точку по потоку ложных заявок. Исследования иерархической классификации описывают накопление ошибок при маршрутизации сверху вниз: [Deep Classification in Large-scale Text Hierarchies](https://home.cse.ust.hk/~qyang/Docs/2008/fp350-xue.pdf). Это гипотеза для наших данных, не обещание прироста.
- **Сильные разреженные базовые модели** нужны раньше большого трансформера: линейный SVM, логистическая регрессия с подбором C, символьные/словесные n-граммы, class weights, смесь синтетики. Поисковое пространство ограничим, выберем по общей `val` и источникам отдельно.
- **Бустинг на эмбеддингах** проверяет нелинейные границы. CatBoost официально поддерживает векторные признаки и создаёт классовые/соседские производные, однако размерность и редкие классы могут помешать: [CatBoost embeddings](https://catboost.ai/docs/en/features/embeddings-features). Сравнивать с линейным классификатором на тех же эмбеддингах.
- **Дообучение энкодера** может адаптировать представления к лексике дома. [Документация Hugging Face по классификации последовательностей](https://huggingface.co/docs/transformers/main/en/tasks/sequence_classification) описывает supervised fine-tuning; [Sentence Transformers](https://www.sbert.net/docs/sentence_transformer/training_overview.html) подчёркивает, что нужное понятие близости зависит от задачи. Сравним плоскую голову и общий энкодер с головами `gate/class/utterance` и маской для неприменимых меток. На GTX 1650 4 ГБ разумный старт — компактный русский энкодер [rubert-tiny2](https://huggingface.co/cointegrated/rubert-tiny2); при успешном запуске — [ruBert-base](https://huggingface.co/ai-forever/ruBert-base) (~178 млн параметров) с короткой последовательностью, малым batch и накоплением градиента. Сам факт большего размера не гарантирует лучший результат.
- **Контрастивное дообучение** полезно для близости сообщений, но позитивы «один класс» не равны «одна заявка». [SetFit](https://arxiv.org/abs/2209.11055) и [label-aware contrastive classification](https://aclanthology.org/2021.emnlp-main.359/) дают идеи, которые применимы после ручных меток инцидентов; пока проверим только классификационный эффект, не объявляя семантическую склейку доказанной.
- **Несколько голов** допустимы как способ разделить цели и совместно учить представление. Экстренность обучается только на safety-разметке, тип высказывания — только там, где он определён; отсутствие метки должно маскироваться, а не превращаться в отрицательную метку. Сравниваем с плоской головой на одинаковых train/val.

## Проверяемые гипотезы и протокол

| № | Гипотеза | Эксперимент | Критерий решения на val |
|---|---|---|---|
| H1 | Плоский классификатор даст выше end-to-end macro-F1, чем gate→class | TF-IDF + LR/SVM/NB, разные C и веса синтетики | macro-F1 по всем реальным WA/TG val; отдельно AP вероятности «проблема» |
| H2 | Семантические эмбеддинги дополнят n-граммы | E5, русские/мультиязычные энкодеры, линейная голова, CatBoost, позднее объединение оценок | Улучшение обоих источников или значимый выигрыш одного без провала второго |
| H3 | Дообученный русский BERT уменьшит ошибки классов | single-head flat vs multi-head на одном энкодере; ранняя остановка по val | end-to-end macro-F1 и gate AP; учитывать обучение и память |
| H4 | Правила склейки слишком консервативны | пороги времени/сходства, `reply_to`, эмбеддинги, модель пар; затем повтор лент | precision/recall/F1 только на слабых парах + ручной аудит вымышленных и обезличенных фрагментов без утверждения incident accuracy |
| H5 | Контекст помогает закрытию и «у нас тоже», но может ухудшить класс | ablation `text`, `text+reply`, локальное окно для спорных реплик | `val` для utterance/класса; отсутствие человеческих инцидентов явно оговорить |

Для каждого подхода фиксируются seed, сплиты, параметры, время, память и размер. Отбор по `val`; не подбирать по test. Основной критерий класса — macro-F1 по всем 34 наблюдаемым меткам, а метрики изолированной головы приводить только как диагностику. Отдельно анализировать хвостовые классы и `not_a_problem`, без уверенных выводов по классам с 1–2 примерами.

## Итоги (27.09.2026)

| Гипотеза | Наблюдение на реальной `val` | Решение |
|---|---|---|
| H1, плоская модель | Лучший разреженный SVM даёт 0,597/0,595 macro-F1 WA/TG; LR с балансировкой 0,635/0,524. Их среднее уступает двум этапам с дообученным энкодером 0,721/0,590. | Плоский вариант остаётся контрольным; в рабочий вариант не выбран. |
| H2, E5 и бустинг | Замороженный E5 как единственный классификатор уступал TF-IDF. Смесь E5 и TF-IDF подняла AP границы с 0,893/0,862 до 0,910/0,883. CatBoost/LightGBM на PCA64 от E5 с лёгким gate дали F1 0,545/0,433 и 0,546/0,410. | E5 используется только в границе проблемы; бустинг отложен. |
| H3, дообучение | Компактный `rubert-tiny2` дал 0,539/0,447 F1 плоской модели и 0,533/0,425 многозадачной. `ruBert-base`, обученный на известных проблемах, дал 0,854/0,758 macro-F1 условной головы класса; с валидированным гибридным гейтом полная цепочка достигла 0,721/0,590. | Использовать сильный энкодер для класса, отдельный гейт для проблемы. Другие головы большого энкодера не обучались и в работе не используются. |
| H4, объединение | Консервативные правила: F1=0,121 на эвристических парах. Простое расширение по классу/подъезду/суткам даёт F1=1,000 на тех же парах, потому что их метки построены почти по этим же признакам. На реальных лентах широкое окно создаёт крупные смешанные группы. | Сохранить консервативную склейку и проверку оператором. Нужна ручная разметка инцидентов. |
| H5, контекст | Добавление текста `reply_to` снизило AP гейта Telegram с 0,862 до 0,836; два предыдущих сообщения — до 0,609. | Не добавлять соседний текст в классификатор сообщения; `reply_to` оставить для поиска связанной заявки. |
| H6, ансамбль класса после первого теста | Усреднение вероятностей ruBERT и лёгкой головы 50/50 улучшило `val` полной цепочки с 0,721/0,590 до 0,763/0,631. | Выбрать ансамбль по среднему F1 на `val`; проверить на `test` один раз. |

Файлы результатов: `experiments/02_classes/flat_sparse_val.json`, `experiments/02_classes/conditional_heads_val.json`, `experiments/02_classes/encoder_base_positive_val_fixedmetric.json`, `experiments/02_classes/encoder_tiny_flat_val_fixedmetric.json`, `experiments/02_classes/encoder_tiny_multi_val_fixedmetric.json`, `experiments/03_embeddings/hybrid_base_val.json`, `experiments/03_context/context_gate_val.json`, `experiments/04_grouping/compare_pairs.json`, `experiments/04_grouping/replay_real_heavy.json`. Ранние измерения некоторых моделей использовали макроусреднение по объединению истинных и предсказанных классов; окончательные значения, включая бустинг и компактный BERT, переоценены по одной основной метрике.

Первый выбранный по `val` вариант один раз оценён на отложенном реальном `test`: AP границы **0,900/0,829** и полная macro-F1 **0,633/0,567** для WA/TG. Затем предложен новый ансамбль, его вес подобран на прежней `val` и он один раз оценён на `test`: полная macro-F1 **0,669/0,571** с групповыми 95% интервалами [0,537–0,693]/[0,507–0,605]. Это повторное использование test для нового подхода, поэтому разницу с первым вариантом следует подтвердить на новом доме или новом размеченном периоде. Результаты — `experiments/03_embeddings/hybrid_base_test.json`, `experiments/02_classes/ensemble_val.json`, `experiments/02_classes/ensemble_test.json`. Метки LLM и исключение спорных сообщений дополнительно ограничивают перенос на живой чат.

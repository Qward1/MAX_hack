# Раунд 2: исследование и гипотезы (26.09.2026)

**Коротко для читателя:** здесь зафиксированы и проверены разные способы определения вида проблемы. Одна модель сразу на 34 класса уступила схеме из двух этапов: сначала определить, есть ли проблема, затем — её вид. Выбрано равное сочетание дообученной ruBERT и модели на сочетаниях букв и слов, при этом первый этап использует E5. Понятное описание устройства и ограничений дано в [главном описании модуля](../README.md#как-устроена-система). Ниже сохранены технические названия моделей, параметров и файлов для повторения опытов.

Этот план зафиксирован **до** новых экспериментов. Никакие тексты не уходят во внешние API; скачивание открытых весов возможно, платные вызовы требуют отдельного согласования. `test` используется после выбора на `val`.

Итоги проверки приведены в конце файла. Исходные гипотезы выше сохранены без ретроспективного редактирования.

## Диагноз первого раунда

- Основная цифра класса должна учитывать **всю** цепочку `gate → fine class` на всех сообщениях. Изолированная голова на заведомых проблемах заметно сильнее полной цепочки: проблемы, пропущенные гейтом, автоматически превращаются в `not_a_problem`.
- Датасет имеет 33 проблемных класса с длинным хвостом. Некоторые встречаются в реальном train 1–10 раз. Искусственные примеры помогают классу, но их стиль отличим. Прогресс нужно мерить против опубликованной базовой линии на **той же постановке**, а не по условной голове.
- Замороженные эмбеддинги E5 без адаптации к этой задаче проиграли символьному TF-IDF на `val`; это не является проверкой дообученного BERT. Обучение только линейной головы не меняет представление коротких бытовых реплик.
- Для склейки нет размеченных инцидентов: `pairs/dev_pairs.jsonl` — эвристические пары, частично определённые классом и временем. Метрики на них могут служить отладкой, а не оценкой качества заявок.

## Обоснование подходов

- **Плоская 34-классовая модель** может убрать накопление ошибок двух этапов. Иерархическую модель оставляем как сравнительный вариант, поскольку она позволяет отдельно задать рабочую точку по потоку ложных заявок. Исследования иерархической классификации описывают накопление ошибок при маршрутизации сверху вниз: [Deep Classification in Large-scale Text Hierarchies](https://home.cse.ust.hk/~qyang/Docs/2008/fp350-xue.pdf). Это гипотеза для наших данных, не обещание прироста.
- **Сильные разреженные базовые модели** нужны раньше большого трансформера: линейный SVM, логистическая регрессия с подбором C, символьные/словесные n-граммы, class weights, смесь искусственных примеров. Поисковое пространство ограничим, выберем по общей `val` и источникам отдельно.
- **Бустинг на эмбеддингах** проверяет нелинейные границы. CatBoost официально поддерживает векторные признаки и создаёт классовые/соседские производные, однако размерность и редкие классы могут помешать: [CatBoost embeddings](https://catboost.ai/docs/en/features/embeddings-features). Сравнивать с линейным классификатором на тех же эмбеддингах.
- **Дообучение энкодера** может адаптировать представления к лексике дома. [Документация Hugging Face по классификации последовательностей](https://huggingface.co/docs/transformers/main/en/tasks/sequence_classification) описывает supervised fine-tuning; [Sentence Transformers](https://www.sbert.net/docs/sentence_transformer/training_overview.html) подчёркивает, что нужное понятие близости зависит от задачи. Сравним плоскую голову и общий энкодер с головами `gate/class/utterance` и маской для неприменимых меток. На GTX 1650 4 ГБ разумный старт — компактный русский энкодер [rubert-tiny2](https://huggingface.co/cointegrated/rubert-tiny2); при успешном запуске — [ruBert-base](https://huggingface.co/ai-forever/ruBert-base) (~178 млн параметров) с короткой последовательностью, малым batch и накоплением градиента. Сам факт большего размера не гарантирует лучший результат.
- **Контрастивное дообучение** полезно для близости сообщений, но позитивы «один класс» не равны «одна заявка». [SetFit](https://arxiv.org/abs/2209.11055) и [label-aware contrastive classification](https://aclanthology.org/2021.emnlp-main.359/) дают идеи, которые применимы после ручных меток инцидентов; пока проверим только классификационный эффект, не объявляя семантическую склейку доказанной.
- **Несколько голов** допустимы как способ разделить цели и совместно учить представление. Экстренность обучается только на safety-разметке, тип высказывания — только там, где он определён; отсутствие метки должно маскироваться, а не превращаться в отрицательную метку. Сравниваем с плоской головой на одинаковых train/val.

## Проверяемые гипотезы и протокол

| № | Гипотеза | Эксперимент | Критерий решения на val |
|---|---|---|---|
| H1 | Плоский классификатор даст выше end-to-end macro-F1, чем gate→class | TF-IDF + LR/SVM/NB, разные C и веса искусственных примеров | macro-F1 по всем реальным WA/TG val; отдельно AP вероятности «проблема» |
| H2 | Семантические эмбеддинги дополнят n-граммы | E5, русские/мультиязычные энкодеры, линейная голова, CatBoost, позднее объединение оценок | Улучшение обоих источников или значимый выигрыш одного без провала второго |
| H3 | Дообученный русский BERT уменьшит ошибки классов | single-head flat vs multi-head на одном энкодере; ранняя остановка по val | end-to-end macro-F1 и gate AP; учитывать обучение и память |
| H4 | Правила склейки слишком консервативны | пороги времени/сходства, `reply_to`, эмбеддинги, модель пар; затем повтор лент | precision/recall/F1 только на слабых парах + ручной аудит вымышленных и обезличенных фрагментов без утверждения incident accuracy |
| H5 | Контекст помогает закрытию и «у нас тоже», но может ухудшить класс | ablation `text`, `text+reply`, локальное окно для спорных реплик | `val` для utterance/класса; отсутствие размеченных инцидентов явно оговорить |

Для каждого подхода фиксируются seed, сплиты, параметры, время, память и размер. Отбор по `val`; не подбирать по test. Основной критерий класса — macro-F1 по всем 34 наблюдаемым меткам, а метрики изолированной головы приводить только как диагностику. Отдельно анализировать хвостовые классы и `not_a_problem`, без уверенных выводов по классам с 1–2 примерами.

## Итоги (27.09.2026)

| Гипотеза | Наблюдение на реальной `val` | Решение | Файл результатов |
|---|---|---|---|
| H1, плоская модель | Лучшие плоские разреженные модели (SVM, LR с балансировкой) уступили двум этапам с дообученным энкодером. | Плоский вариант остаётся контрольным; в рабочий вариант не выбран. | `experiments/02_classes/flat_sparse_val.json` |
| H2, E5 и бустинг | Замороженный E5 как единственный классификатор уступил TF-IDF. Смесь E5 и TF-IDF подняла AP первого этапа. CatBoost/LightGBM на PCA64 от E5 уступили. | E5 используется только в границе проблемы; бустинг отложен. | `experiments/03_embeddings/hybrid_base_val.json`, `experiments/02_classes/conditional_heads_val.json` |
| H3, дообучение | Компактный `rubert-tiny2` (плоский и многозадачный) оказался слабее. `ruBert-base`, обученный на известных проблемах, вместе с гибридным гейтом дал лучшую полную цепочку. | Использовать сильный энкодер для класса, отдельный гейт для проблемы. Другие головы большого энкодера не обучались и в работе не используются. | `experiments/02_classes/encoder_base_positive_val_fixedmetric.json`, `experiments/02_classes/encoder_tiny_flat_val_fixedmetric.json`, `experiments/02_classes/encoder_tiny_multi_val_fixedmetric.json` |
| H4, объединение | Слабые пары построены почти по тем же признакам (класс, подъезд, время), что и простые правила, поэтому расширение правил выглядит на них идеальным. На реальных лентах широкое окно создаёт крупные смешанные группы. | Сохранить осторожную склейку и проверку оператором; для оценки нужна ручная разметка инцидентов. | `experiments/04_grouping/compare_pairs.json`, `experiments/04_grouping/replay_real_heavy.json` |
| H5, контекст | Добавление текста `reply_to` и предыдущих сообщений снизило AP гейта. | Не добавлять соседний текст в классификатор сообщения; `reply_to` оставить для поиска связанной заявки. | `experiments/03_context/context_gate_val.json` |
| H6, ансамбль класса после первого теста | Усреднение вероятностей ruBERT и облегчённой головы 50/50 улучшило полную цепочку на `val`. | Выбрать ансамбль по среднему F1 на `val`; проверить на `test` один раз. | `experiments/02_classes/ensemble_val.json` |

Ранние измерения некоторых моделей использовали макроусреднение по объединению истинных и предсказанных классов; окончательные значения, включая бустинг и компактный BERT, переоценены по одной основной метрике (файлы `*_fixedmetric.json`).

Первый выбранный по `val` вариант один раз оценён на отложенном реальном `test`; затем предложен ансамбль, его вес подобран на прежней `val`, и он тоже один раз оценён на `test`. Это повторное использование test для нового подхода, поэтому разницу между вариантами следует подтвердить на новом доме или новом размеченном периоде. Результаты — `experiments/03_embeddings/hybrid_base_test.json`, `experiments/02_classes/ensemble_test.json`.

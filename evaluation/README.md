# Оценка AI-ядра

```bash
uv run python evaluation/run_eval.py --provider rules --out evaluation/reports/
uv run python evaluation/run_eval.py --provider fake  --out evaluation/reports/
```

Сети, ключей и PostgreSQL не требуется. Отчёт пишется парой файлов
`<дата>-<провайдер>-<версия правил>.md` и `.json`.

> **Числа отчёта — внутривыборочная оценка на синтетике, а не оценка
> качества.** Ограничения наборов описаны в [datasets/README.md](../datasets/README.md).

## Что измеряется

| Набор | Как прогоняется | Метрики |
|---|---|---|
| `single_messages.v1` | каждое сообщение — окно `group_report` из одной реплики | роль, категория точно и по пересечению, доля определённых подтипов, пропущенные и ложные проблемы, опасность (найдено/ложные), подъезд, recall-гейт E0b |
| `scope_and_danger.v1` | сообщения — окна из одной реплики; окна — как есть | роль, `location_scope`, точность подтипа, поведение правил на контекстной опасности |
| `chat_stream.v1` | поток режется `windowing.py` (120 с тишины / 10 реплик / 300 с возраста / опасность — сразу), к каждому окну прикладываются до 5 предыдущих реплик как контекст | recall значимых реплик (`new_problem`, `me_too`, `more_info`, `objection`), лишние реплики, recall инцидентов, доля потока в Inbox и в Audit Pool |
| `dedup.v1` | каждый запрос — окно из одной реплики с 10 открытыми элементами | верные привязки, привязки не к тому элементу, пропущенные и ложные привязки |

Доли сопровождаются интервалами Уилсона 95 %. `sklearn` не используется.

## Режимы провайдера

- `--provider rules` — модель не вызывается, работает детерминированный «пол».
  Только к этому режиму применяются регрессионные полы.
- `--provider fake` — детерминированный Fake без сети. По умолчанию он
  отвечает «ничего не нашёл», поэтому прогон проверяет ветку модели,
  валидатор и Emergency Fusion (опасность правил переживает молчание модели),
  а не качество разбора. Полы регрессии к нему не применяются.

## Регрессионные полы (режим правил)

| Пол | Порог |
|---|---|
| типичный срез: категория | ≥ 0,95 |
| типичный срез: роль | ≥ 0,95 |
| пропущено проблем | ≤ 8 из 66 |
| ложных проблем | ≤ 2 из 32 |
| срез опасности | 10 из 10 |
| гейт E0b на проблемах | ≥ 64 из 66 |
| поток E0c, вариант C: recall значимых реплик | ≥ 0,70 |

Те же полы проверяет `tests/ai/test_regression_floors.py`, поэтому регрессия
ловится обычным прогоном тестов, а не только отдельным запуском оценки.

## Воспроизводимость

В JSON пишутся дата, git SHA, версии таксономии/правил/схемы и SHA-256 каждого
набора. Единственное поле, различающееся между прогонами, — `generated_at`.
Времени выполнения в отчёте нет намеренно: оно сделало бы отчёт
невоспроизводимым.
